# The arms

### Reference (both providers)
- **`baseline`** — uncompressed 125k-token haystack, single LLM call
- **`headroom_default`** — Headroom `ContentRouter`, ~54% compression, single LLM call

### Provider-native compaction
- **`anthropic_compact_v2`** — server-side `compact_20260112`, Sonnet 4.6
- **`openai_compact_v2`** — server-side Responses API `context_management`, gpt-5.4

### Floor tests (Anthropic side only — matched compression at 54%)
- **`dumb_truncation_last_n`** — keep last 46% of tokens, drop the rest
- **`random_chunk_drop`** — deterministic random chunk drops to matched ratio

<!--

# 🎯 The floor-test finding

## At matched 54% compression ratio

| arm | compression | quality | Δ vs Headroom |
|---|---:|---:|---:|
| **headroom_default** | 54.2% | **84.0%** | — |
| dumb_truncation_last_n | 54.0% | 28.0% | <span class="loss">**−56.0 pp**</span> |
| random_chunk_drop | 53.8% | 22.0% | <span class="loss">**−62.0 pp**</span> |

## The "just less text" hypothesis is falsified

> At the same compression ratio as Headroom, naive compression scores **10 to 16 percentage points WORSE than baseline**.
>
> Headroom at the same ratio scores **46 percentage points BETTER than baseline**.
>
> **The gap between Headroom and naive compression at matched ratio is 56 to 62 percentage points.**

Headroom's query-aware `ContentRouter` selection is doing the entire lift.

# The cost story

## Headroom saves ~54% per case on **both** providers

| Provider | baseline $/case | Headroom $/case | Δ |
|---|---:|---:|---:|
| Anthropic Sonnet 4.6 | $0.3757 | $0.1727 | <span class="win">**−54.0%**</span> |
| OpenAI gpt-5.4 | $0.2836 | $0.1301 | <span class="win">**−54.1%**</span> |

### Why the savings are structural

- Headroom compresses **before** the API call · provider bills ~58k input tokens
- Both provider-native compaction features happen **after** tokens are billed · cost-neutral in one-shot
- **Only a pre-API layer captures input-token savings**

### Illustrative annualised scaling at 10k requests/day

| Provider | Baseline | Headroom | **Annual savings** |
|---|---:|---:|---:|
| Anthropic Sonnet 4.6 | $1.37M | $630k | <span class="win">**$741k**</span> |
| OpenAI gpt-5.4 | $1.04M | $475k | <span class="win">**$560k**</span> |

# Why Headroom wins on quality

## Query-aware vs query-blind at the compression step

- **Headroom** knows the question at compression time
  → scores each chunk for relevance to the query
  → preserves needles, drops distractors

- **`anthropic_compact_v2`** has to compress *before* seeing the question
  → applies a generic salience prior
  → preserves identity-defining facts (degrees, jobs, ages)
  → **drops incidental-looking facts** (commute times, phone numbers, favorite restaurants)
  → on LongMemEval ~half the questions ask about those incidental facts
  → lands at **54.0%** correct — exactly matching this prediction

**Structurally different approaches to compression. On conversational fact-recall, query-awareness wins.**

<!--
Speaker notes:
- This is the "why does compact_v2 lose" explanation. It's not that
  Anthropic's feature is bad — it's that prospective summarization is
  structurally different from query-aware retrieval.
- The specific failure mode we verified in smoke testing: the commute
  case. Question: "How long is my daily commute?" Ground truth: "45
  minutes each way" (verbatim in the haystack). Compaction summary:
  "the user never mentioned anything about a daily commute."
- The model got the degrees right because "Business Administration" is
  the kind of identity-defining fact the prospective summarizer preserves.
  It got the commute wrong because 45 minutes is incidental-looking.
- Fair framing: Anthropic's feature is exactly what it says on the tin,
  designed for agent-continuation workflows. Not the right tool for
  conversational fact-recall on LongMemEval's question shape.

# Corrections that happened during this work

Two important corrections worth naming upfront:

### 1. Anthropic `compact_20260112` existed — we missed it initially

- Shipped **2026-01-12** on Sonnet 4.6 / Opus 4.6 / Mythos Preview
- Our installed SDK (`anthropic==0.76.0`) had no typed shapes
- I read the older deprecated `tool_runner(compaction_control)` SDK path instead of the live docs
- **Fix:** upgraded to SDK 0.92.0, wired `AnthropicCompactV2Runner`, ran the real head-to-head

### 2. OpenAI Responses API compaction existed — we misdiagnosed it initially

- Shipped on `gpt-5.3-codex` / `gpt-5.4`
- The Apr 8 probe ran on **`gpt-4o-mini`**, which is NOT in the supported-models list
- Returned a degenerate analytics-only response (because the model isn't trained to produce real compaction items)
- **Fix:** reran on `gpt-5.4`, wired `OpenAICompactV2Runner`, verified with 2/2 smoke, then N=50

**The corrected framing is stronger, not weaker.** Both vendors confirm context compaction is worth solving at the platform layer.

# Caveats — what we did NOT measure

1. **One benchmark family.** LongMemEval `single-session-user` only. Sonnet 4.5 N=150 ablation replicates the shape across 3 question types, but we haven't tested the other 5 types on Sonnet 4.6 or any on gpt-5.4.
2. **Two models.** Sonnet 4.6 and `gpt-5.4`. No Opus 4.6, no other GPT-5 variants, no non-frontier models.
3. **No tool-using / agentic workload.** τ-bench is the honest home for the old `tool_runner(compaction_control)` comparison.
4. **No running-conversation workload.** `openai_compact_v2`'s benefit model is multi-turn; one-shot benchmarks don't exercise it.
5. **No real orq production workload.** Headroom reproduction found 0% compression on orq traces due to double-encoded JSON strings — Karina's JSON-unwrapping fix lands separately.
6. **LLM-as-judge, not human eval.** Haiku 4.5 judges against ground truth. Given the size of the deltas we're comfortable, but Phase 2 could cross-judge.

# ✅ Recommendation

## Ship Headroom behind a feature flag for long-context workloads on both OpenAI and Anthropic surfaces

**No Phase 2 gate.** The data is measured, the comparison is head-to-head against provider-native alternatives, and the methodological robustness check is passed.

### Three independent bodies of evidence

1. **Head-to-head at N=50 on both providers** — wins on every axis measured
2. **Floor-test finding** — 56–62 pp gap at matched compression falsifies the "just less text" hypothesis
3. **Cross-provider structural argument** — Headroom is the only layer that is identically-shaped across providers, transparent, query-aware, deterministic, and runs pre-API so cost savings are captured at the input layer
